# 非遗之手

按两张确认的原型实现的陶艺教学工作台、手机端交互界面与微信原生小程序工程。

## 打开

用户操作请先阅读[电脑 Web 使用说明书](../../03_项目文档/04_使用说明/电脑Web使用说明书.md)。本机双击 `启动非遗之手.cmd`。Git 源码不包含依赖和构建产物；新电脑需安装根目录及 desktop、mobile 依赖，再执行 `npm run build` 与 `npm start`，详见说明书附录。

- 电脑端：http://localhost:4180
- 手机端浏览器预览：http://localhost:4180/mobile/
- 微信小程序：在微信开发者工具中导入 `miniprogram` 目录。当前使用 `touristappid`，预览/上传到真实微信账号需要填写自己的 AppID；本次没有发布或上传。

浏览器手机端保留了手机外观与键盘交互，用于查看与操作手机页面。它与原生微信工程是两个运行入口，不应把浏览器预览称为已经通过微信真机验收。

## 已实现

- 两端按原型实现的导航、学习、设备、校准、手势、训练、报告和历史页面。
- 提供的三段揉泥视频，转为本地可播放的 H.264 视频；无需云端视频地址。
- 电脑与浏览器手机端共用一个本地服务，开始、暂停、恢复、结束与报告同步。
- 微信端默认独立使用本机存储；设置工作台服务地址后切换到共享服务。两种存储不会自动合并。
- 真实五路数值的校验、曲线展示、模板录入、容差匹配、持续匹配计数、报告和 JSON/CSV 导出。
- 串口和 BLE 接入代码，设备过期断连显示、无数据保护、异常提示。
- 电脑浏览器语音反馈，微信端本地语音提示。

## 硬件接口现状

**最新实物进展：电脑蓝牙 → 手套 → 工作台五路实时曲线已跑通。** 点击设备页“扫描蓝牙手套”，选择Glove后连接。实时预览不自动开始练习、不生成报告；模式查询、模式往返切换及断开重连已有实物验证。蓝牙硬件校准及保存已开放并收到过实物确认，首页新增实时校准弹窗。硬件槽位录入会覆盖原槽位；不要把控制入口存在等同于所有录入场景均已验收。当前匹配和语音问题见[最新归档状态](../../03_项目文档/03_梳理报告/GitHub归档与当前状态_2026-09-14.md)。

新增 `hardware/ble_worker.py` 使用Python Bleak，通过本机子进程把通知交给Node；`ble-port.mjs` 管理扫描、连接、断开及受限命令；`ble-stream.mjs` 从混合数据中区分二进制心跳/事件与UTF8文本。电脑本地依赖已装好；迁移机器需安装Python并执行 `python -m pip install --target hardware/python-deps -r hardware/requirements.txt`。可设置 `POTTERY_PYTHON` 指定解释器；当前机器会自动寻找已验证的本机Python运行环境。[Bleak官方用法](https://bleak.readthedocs.io/en/latest/usage.html)

无线命令使用小写发送：固件会把大写U（0x55）误作二进制帧头，导致STATUS变成STATS；实物已验证小写status正确回复。无线STATUS仅确认模式，不能据此认定已读取全部模板，LIST完整输出只到USB。

以下为此前USB阶段的基线说明，实物进展以上述蓝牙结果和开发记录为准。

**USB阶段：首批真实协议接入代码已完成，USB实物收发尚未验证。** 使用“电脑主机＋小程序辅助”。完整路线见[开发计划](../../03_项目文档/03_梳理报告/软件开发与整机联调计划.md)，本批实现与验证见[设备接入进展](../../03_项目文档/03_梳理报告/设备接入开发进展_2026-09-14.md)。

电脑“设备与校准 → 真实手套接入”选择串口，Node服务以9600连接硬件组 pottery v2.1 文本协议：

```text
D,500,1000,1500,2000,2500
MODE:0
OK:G=0
ERR:mask=0
```

五路顺序为拇指、食指、中指、无名指、小指，范围500–2500，是映射后的弯曲采样值。模式0提供连续数据；原固件模式1只有识别事件，没有连续D帧。连接存活、采样是否更新、识别事件是否过期分别显示。错误文本不含模板ID，不能自行补出ID；硬件通知条数也不等于完成动作次数。

支持模式、硬件校准、0–9槽位录入、LIST、SAVE、LOAD等命令。只有收到对应设备回执才显示确认；超时后阻止后续命令并要求重连检查。首次打开不主动发送命令；若原设备处于安静的识别状态，可手动点击采集模式0。配置修改在练习期间受限。设置页的“设备指令”也走同一主机服务。

“真实手套接入”操作手套；下方“软件个人参考”及软件手势管理保存本地参考，两套模板尚未自动同步。硬件校准保护检查每根手指的变化，但不能代替固件自身对零分母的修复。SAVE确认不等于已验证断电保持，需实物重启验收。

微信原生小程序设置电脑服务地址后，可查看主机状态、发起模式/校准/保存请求，与电脑共享练习和报告；此模式不再扫描手机BLE。手机浏览器端可查看电脑连接状态。真实微信编译、网络配置和双端实物控制仍待验证。

旧版通用CSV/JSON、浏览器BLE及微信独立BLE代码仍保留，用于其他设备；它们没有适配本次手套的混合BLE协议，不是本次默认接入路线。设置页通用波特率不改变真实手套服务固定的9600。串口由电脑服务占用时，接口拒绝混入其他来源采样。

硬件JQ8900/STM32播报尚未与平台统一判定来源；现在的软件语音仍是软件提示。摄像头程序已归档，尚未接入工作台，当前视频区域播放教学参考视频。未训练视觉AI，未将模板匹配解释为陶艺专业评分。

未连接手套也可以观看视频、记录自主练习时长；没有数据时不填充姿态成绩。

## 文件与数据

- `desktop/`：电脑端 React/Vite 工程。
- `mobile/`：手机交互界面及原有移动运行壳。
- `miniprogram/`：可导入微信开发者工具的 WXML/WXSS/JS 原生工程。
- `core.mjs`：会话、校准、模板、评价与记录逻辑。
- `server.mjs`：本地 HTTP 服务，静态页面及共享数据接口。
- `hardware/`：真实协议解析、串口网关、会话原始日志。
- `media/`：教学视频及语音文件。
- `data/studio.json`：模板、设置、已结束的学习报告。
- `data/sessions/*.jsonl`：每次练习的采样、硬件事件、命令回执和开始时的软件参考快照。备份整个data目录。未结束练习的业务状态仍在内存中；意外退出后的日志恢复尚未实现。
- `qa/`、`design-qa.md`：界面和交互验收记录。

服务用于可信任的本机/局域网，尚未实现账号认证或公网部署。手机连接局域网服务时，填写电脑的局域网地址及4180端口；微信平台对网络地址和发布域名有自己的校验要求。正式上线需完成相应账号与域名配置。

## 开发与验证

```powershell
npm ci
npm --prefix desktop install
npm --prefix mobile ci
npm test
npm run build
npm run dev
```

开发端口：电脑4173，手机4174，共享服务4180。生产入口由4180同时提供两端页面。

测试区分本地逻辑测试、浏览器交互验收与实物联调；前两者通过不代表最后一项已完成。微信原生页面有离线行为测试和资源/语法检查，尚未在微信开发者工具或真实手机中编译验证。
